Building Responsibly

Sustainable Web Design

The internet has a carbon footprint. Every page load, every image, every animation uses energy. This site was built with sustainability as a core requirement—here's how and why.

Why This Matters

The internet accounts for about 4% of global carbon emissions—roughly equal to the aviation industry. Every website contributes. While a single page load seems insignificant, multiply it by millions of visitors and thousands of sites, and the impact becomes substantial.

As product managers and developers, we make hundreds of small decisions that affect energy consumption. Choosing to load a 2MB hero image versus a 100KB optimized one. Using system fonts instead of web fonts. Lazy-loading images. These decisions compound.

This site demonstrates that you can build something beautiful, interactive, and functional while minimizing environmental impact. It's also a portfolio piece—showing that I think about sustainability not as an afterthought, but as a design constraint that breeds creativity.

Technical Decisions

📝

System Fonts Instead of Web Fonts

Web fonts require additional HTTP requests and downloads. System fonts are already on your device.

Typical Approach

Google Fonts or self-hosted fonts: 50-200KB additional download, blocking render until loaded

This Site

System font stack: 0KB additional download, instant rendering, native feel on each platform

🌙

Dark Mode as Default

OLED screens use less energy displaying dark pixels. Dark mode reduces power consumption by up to 60% on OLED displays.

Typical Approach

Light mode default, dark mode as optional afterthought

This Site

Dark mode default, respects system preference, saves preference to localStorage

🖼️

Lazy Loading Everything

Only load resources when they're needed. If you never scroll to an image, why download it?

Typical Approach

Load all images on page load, even those below the fold

This Site

Native lazy loading, images only load when scrolled into view

⚡

No Heavy Build Tools

No React, no Webpack, no npm build process. Just HTML, CSS, and vanilla JavaScript.

Typical Approach

React + Webpack: 150KB+ JavaScript bundle, hydration costs, build complexity

This Site

Vanilla JS: <20KB total scripts, no hydration, instant interactivity

🔋

Low Power Mode Detection

Automatically reduce resource usage when your device battery is low.

Typical Approach

No consideration for device battery status

This Site

Detects battery <20%, disables animations, skips non-essential images

📄

Static Site Architecture

No server-side processing, no database queries. Just files served from a CDN.

Typical Approach

Dynamic CMS: Database queries on every request, always-on servers, complex infrastructure

This Site

Static files on GitHub Pages (renewable energy), cached at edge locations, no processing per request

Sustainability Checklist

Features implemented on this site:

  • ✓ System fonts only (no web font downloads)
  • ✓ Dark mode default with system preference detection
  • ✓ Lazy loading for all images
  • ✓ No unnecessary JavaScript frameworks
  • ✓ Low power mode detection
  • ✓ Respects prefers-reduced-motion
  • ✓ Service worker for offline caching
  • ✓ Hosted on green-powered infrastructure (GitHub Pages)
  • ✓ Minimal external dependencies (only Leaflet.js for maps)
  • ✓ Page weight under 500KB including images
